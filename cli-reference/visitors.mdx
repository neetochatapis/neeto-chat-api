Commands for the people who chat with a workspace. The API calls this
resource a contact; the CLI calls it a visitor. For fields and response
details, see the [Contacts API reference](/api-reference/contacts/list).

Samples on this page use `--json`, which is the format you get when output is
piped as well. On a terminal without that flag the same data prints as a table.
See [Output formats](/cli/output-formats).

## List visitors

Visitors in the workspace, oldest first. `--email` and `--user-identifier`
are not unique: the chat widget creates a separate visitor for each browser a
person chats from, so either filter can return more than one match.

```bash
neetochat visitors list --json
```

## Show a visitor

One visitor by id, when you already have it and want the full record.

```bash
neetochat visitors show 2c79a334-0bc8-44e4-9504-331f59d400ab --json
```

**Required arguments:**

| Argument | Description |
| --- | --- |
| `<id>` | The visitor's UUID, from `neetochat visitors list`. |

This command takes no flags of its own.

```json
  "data": {
```

## Create a visitor

Adds a visitor to the workspace. Every field is optional; the name defaults
to `Visitor` when left out.

```bash
neetochat visitors create \
  --name "Sam Brown" \
  --email sam@example.com \
  --user-identifier customer-1042 \
  --trait plan=Pro
```

```json
    }

```

`--trait` sets a free-form custom attribute and can be repeated for more than
one, for example `--trait plan=Pro --trait country=US`. `--field` sets a value
for one of the workspace's contact fields instead, keyed by the field's UUID
rather than its name: `--field 7f1f1f36-1f0f-4a0e-9b1f-2b0f3c4d5e6f=Enterprise`.

<Tip>
  With `--quiet` the command prints only the new record's identifier, which is
  convenient in a script.
</Tip>
